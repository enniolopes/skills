# APPLY intent — operate the brand in a real touchpoint

APPLY creates a new branded artifact from the current spec. It uses the global **SEARCH → PROVE → COMMIT → ADAPT** loop and does not redesign the brand by default.

Use for decks, pages, reports, campaigns, social assets, emails, documents, UI surfaces, signage and other touchpoints when a current spec exists.

## SEARCH

### Inspect the smallest sufficient context

Read:
- current brand spec;
- the source content/artifact;
- relevant examples/assets;
- medium-specific constraints;
- `identity-craft.md` when visual composition is involved.

Compile only the spec subset that governs this artifact. Typical packet:
- relevant strategy/audience goal;
- voice/tone for the moment;
- identity grammar and distinctive devices;
- applicable type/color/composition rules;
- relevant exclusions;
- production/accessibility constraints.

Do not dump the whole brand system into working context when a smaller packet is sufficient.

### Resolve the job autonomously

Infer from the request and available evidence:
- audience;
- desired action/communication outcome;
- medium/dimensions;
- required content;
- moment/tone;
- production/accessibility/regulatory constraints.

Use a Truth/Authority gate only when a missing fact materially changes the artifact. Do not ask for routine aesthetic preferences.

### Explore only when it adds value

For an ordinary application, compose directly from the grammar.

For a consequential or novel touchpoint, SEARCH may explore several materially different compositional lineages internally, then prune before delivery.

## PROVE

Use the verification level justified by the artifact's commitment radius.

### V1 Structural
Run deterministic checks available for the medium:
- exact tokens/contrast where inspectable;
- logo master integrity;
- document/code/file validation;
- required dimensions/variants;
- accessibility rules that are machine-checkable.

### V2 Semantic
Check:
- Does the artifact accomplish its job?
- Is it recognizably generated by the brand grammar rather than merely logo-stamped?
- Does hierarchy support the communication goal?
- Does tone fit the moment?
- Are distinctive devices coherent rather than decorative?
- Are any spec rules being followed mechanically at the expense of communication?

### V3 Contextual
Render/inspect the artifact in its real or representative context when the host supports it. Correct visible/interaction failures before user review.

V4 is needed only when the application makes claims about real audience effect or other external outcomes.

## COMMIT

For LOCAL application choices, decide autonomously.

Commit the requested artifact only after applicable verification. Deliver the preferred result, not an unranked menu of variants.

Do not mutate the spec casually. If the work reveals a problem, classify it:
- **artifact failure** — fix only the artifact;
- **recurring guidance gap** — propose/commit a small SYSTEM patch when justified;
- **system failure** — create an EVOLVE candidate.

A one-off application difficulty is not evidence that the brand needs redesign.

## ADAPT

Record only outcomes that improve future decisions:
- a recurring failure exposed by the touchpoint;
- a rule that required a system patch;
- new external evidence that challenges a belief;
- meaningful production constraints.

Do not add every application to persistent history.

## Delivery

Deliver:
- the requested artifact;
- concise rationale linked to relevant spec rules;
- applicable V1/V2/V3 verification results;
- unresolved evidence/craft issues only if material;
- any proposed spec change clearly separated from the artifact itself.
