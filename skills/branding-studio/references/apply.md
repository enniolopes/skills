# APPLY mode — create a branded touchpoint from an existing spec

APPLY operationalizes an existing brand system. It does not redesign the brand by default.

Use it when the user asks for a deck, page, report, social asset, campaign element, email, document, UI surface, signage concept or other branded artifact and a current brand spec exists.

## 1. Load the contract

Read:
- current brand spec;
- relevant source artifact/content;
- touchpoint-specific constraints;
- `identity-craft.md` when visual composition is involved.

Identify which spec rules actually govern this artifact. Do not dump the entire brand system into context when only a subset is relevant.

## 2. Define the application job

Resolve:
- audience;
- communication/action goal;
- medium and dimensions;
- required content;
- production constraints;
- moment/tone;
- accessibility or regulatory constraints if applicable.

Ask only for missing facts that materially change the result.

## 3. Compose from the brand grammar

Use the identity as a language, not a template prison.

Preserve:
- strategy/theme;
- voice;
- visual principles;
- distinctive assets;
- semantic tokens/rules where relevant.

Adapt:
- hierarchy;
- density;
- tone by moment;
- composition;
- media-specific behavior.

A valid application can look different from previous examples while remaining generated by the same grammar.

## 4. Check before delivery

Run deterministic checks available for the medium:
- declared color/token constraints;
- contrast where relevant;
- SVG checks for logo masters used;
- document or code validation if the host provides it.

Then perform semantic review:
- Does the artifact accomplish its job?
- Is the brand recognizable without relying only on the logo?
- Does hierarchy support the communication goal?
- Does voice fit the moment?
- Are any spec rules being obeyed mechanically at the expense of the artifact?

## 5. Do not mutate the spec casually

If the application exposes a problem, classify it:

- **application problem** — fix the artifact;
- **missing guidance** — propose a patch to the spec if the omission will recur;
- **system failure** — route to EVOLVE if the current brand grammar cannot serve an important legitimate touchpoint.

Do not silently change the brand to make one artifact easier.

## Delivery

Deliver:
- the requested artifact;
- a concise application rationale linked to the relevant spec rules;
- deterministic check results where available;
- semantic self-audit;
- any proposed spec change clearly separated from the application itself.
