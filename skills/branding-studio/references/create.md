# CREATE — establish or reconstruct a brand system

Use CREATE for a genuinely new brand, a material re-foundation, or an existing identity that needs a canonical operating contract. Run the full workflow in `SKILL.md`; this reference holds only what CREATE adds.

## Existing identity: decide what survives first

Absence of a spec does not imply absence of brand equity. Before generating anything, inspect what exists (name, assets, language, recurring behavior, how people already recognize the brand) and classify each important element as **preserve, refine, replace, retire or add**. Do not redesign merely to make the work feel new or to populate a schema. Reconstruction still ends in rendered boards: the owner sees what was recovered and what is proposed to change.

## Frameworks earn their place

A framework belongs only when it changes a material decision. Do not manufacture archetypes, manifestos, onliness statements, category-entry-point maps or purpose language by default.

## System scope follows the touchpoints

Load `identity-craft.md`; load `verbal-identity.md` only when proposition, messaging, voice or a broader verbal system is materially in scope; `naming.md` when naming is. Define only the dimensions the declared touchpoints need. A grammar that can generate new work is the goal, not a checklist of brand ingredients.

Use the trials on the declared touchpoints to expose missing guidance, not just execution defects: when a legitimate application forced a brand-level decision the system did not provide, and the same gap recurs across materially different applications, repair the grammar and re-test. If every application needs the same layout or logo placement to look on-brand, the grammar is under-resolved.

## Maturity

**Provisional** when the business thesis, offer, market or identity still has material uncertainty and the immediate goal is a coherent, promotable system for current touchpoints. **Full** only when the work justifies production-grade depth across durable touchpoints. Full means the material system and production dependencies are resolved, not that more fields are filled.

## Delivery

The package (book and assets, in the audience's language) with the contextual renders of the declared touchpoints; the contract as a separate operating file; rationale, verification performed and unresolved dependencies reported to the operator, never inside the package.
